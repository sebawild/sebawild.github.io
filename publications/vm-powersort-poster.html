Virtual-Memory Powersort

Stable, run-adaptive mergesort with O(√(n log n)) extra space instead of a buffer for n/2 elements — at almost no cost in running time.

Finn MoltmannTamio-Vesa NakajimaSebastian WildPhilipps-Universität Marburg

ESA 2026

powersort in one picture

Powersort (Munro & Wild, 2018) merges natural runs in nearly optimal order

  1. Runs. One scan chops the input into already sorted runs (lime boxes).
  2. Powers. For each boundary, the interval between the midpoints of its two runs drops onto a virtual balanced tree. The depth of the tallest pole it lands on is the boundary's power (chip).
  3. Stack. Runs wait on a stack with increasing powers; a boundary with a smaller power triggers the merges above it — that is the whole policy.

merge cost M ≤ n (H + 2), H = run-length entropy — optimal up to a linear term. Default list.sort policy in CPython since 3.11.

the catch

Every Timsort/Powersort implementation copies the smaller run to a buffer of n/2 elements before merging. In-place merging exists but is several times slower. Idea: decouple where a run lives from where it came from.

virtual-memory powersort

Runs are lists of pages — permuted in memory, sorted in order

one colour per run (detected or merged)  ·  free page  ·  not yet scanned  ·  final sorted output. Example: n = 40, P = 4, four extra pages.

pingpong powersort

With a full-size buffer, Powersort's choreography avoids every extraneous copy

empirical results

Quadratically less memory, negligible slowdown

T = record size in words · M = merge cost of Powersort (sum of merge input lengths), M ≤ n(H + 2)

  • Memory drops by two to three orders of magnitude: 0.5–3 % of the input instead of 50 % (1–6 MB instead of 18–543 MB).
  • Running time stays within roughly 10–30 % of the CPython-style variant for small records — and is faster on 1 GB of randomBlob30 input (less memory touched).
  • Black-box in-place merging is 4–7× slower, and Wikisort is slower and not fully run-adaptive; clever page management is what makes almost-in-place sorting practical.
  • Fewer moves pay off for large records: Pingpong Powersort is fastest on zeroBlob30 (slow compare, slow move).
  • Theory predicts practice: comparisons coincide for all Powersort variants; move counts follow M + 3n, M + n and 1.5M + n.
