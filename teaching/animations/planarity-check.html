Planarity testing  ·  lowpoints and the left-right test

A DFS orients every edge of an undirected graph into a tree edge or a back edge. The lowpoint of an edge is the height of the lowest vertex its subtree reaches back to; it is the basic quantity behind cut vertices and behind the left-right planarity test. DFS trees are drawn growing upwards: the root is at the bottom, so “lower” means closer to the root. Hover an edge to see its return edges.

About this tab: what lowpoints are and how one DFS computes them

DFS in an undirected graph

Depth-first search on an undirected graph \(G=(V,E)\) meets every edge twice, once from each end. The first time an edge \(\{v,w\}\) is looked at from \(v\), it is either a tree edge \(v \to w\) (\(w\) was unseen and is discovered now) or a back edge \(v \hookrightarrow w\) (\(w\) is still active, i.e., an ancestor of \(v\) on the stack). Forward and cross edges do not occur: an edge to a finished vertex has already been traversed from its other end. We orient every edge in the direction of its first traversal. The height of \(v\) is its distance from the root in the DFS tree. Trees are drawn growing upwards: the root is at the bottom, so “lower” means “closer to the root”.

Return edges and lowpoints

A back edge \(x \hookrightarrow u\) is a return edge of the tree edge \(v \to w\) if \(x\) lies in the subtree of \(w\) and \(u\) lies strictly below \(v\); \(u\) is then a return point of \(v\to w\). A back edge is its own (and only) return edge. The lowpoint \(\id{lowpt}(e)\) is the height of the lowest return point of \(e\), or the height of the source of \(e\) if \(e\) has no return edge. Back edges from the subtree of \(w\) that end at \(v\) itself are not return edges of \(v \to w\). Hover an edge in either drawing to see its return edges.

One DFS computes all lowpoints

Lemma. For a tree edge \(v\to w\): \(\id{lowpt}(v\to w) = \min\bigl(\{\id{height}(v)\} \cup \{\id{lowpt}(f) : f \text{ an outgoing edge of } w\}\bigr)\). So the lowpoint of an edge is final as soon as everything above it has been explored, and the DFS can compute all of them bottom-up. The pseudocode is the iterative dfs with hooks:

  • preorderVisit(\(w\)): the tree edge \(u\to w\) has just been taken; \(\id{height}(w) = \id{height}(u)+1\) and \(\id{lowpt}(u\to w)\) starts at \(\id{height}(u)\) (no return edge known yet).
  • visitEdge(\(vw\)): if \(w\) is active and not the parent of \(v\), the edge is a back edge \(v\hookrightarrow w\) with \(\id{lowpt} = \id{height}(w)\); it is folded into the parent edge of \(v\) at once. Otherwise the edge is a tree edge (handled by preorderVisit) or was already oriented from the other end.
  • postorderVisit(\(w\)): \(w\) is finished, so the tree edge \(v\to w\) is fully explored; fold it into the parent edge of \(v\).
  • foldIntoParent(\(v, f\)): \(\id{lowpt}(e) \gets \min\{\id{lowpt}(e), \id{lowpt}(f)\}\) for the parent edge \(e\) of \(v\) — this is the lemma, applied one outgoing edge \(f\) at a time.

Every edge is handled a constant number of times: \(\Theta(n+m)\) time.

Application: cut vertices

A tree edge \(v\to w\) has no return edge iff \(\id{lowpt}(v\to w) = \id{height}(v)\); then every path from the subtree of \(w\) to the rest of \(G\) passes through \(v\). Hence a non-root vertex \(v\) is a cut vertex iff some child \(w\) has \(\id{lowpt}(v \to w) = \id{height}(v)\), and the root is a cut vertex iff it has at least two children. The last step marks them (dashed rings) together with the tree edges without return edge.

About this tab: the left-right criterion, interactively

Fundamental cycles and forks

A DFS orients \(G\): tree edges point away from the root, back edges \(x \hookrightarrow u\) point to an ancestor. Every back edge \(b\) closes a fundamental cycle \(C(b)\): the tree path from \(u\) up to \(x\), then \(b\). Two fundamental cycles either share no tree edge or overlap in a tree path \(v_1 \to \cdots \to v_k\). The last shared tree edge \((v_{k-1}, v_k)\) together with the two edges \(e_1, e_2\) out of the branching point \(v_k\) through which the cycles continue is their fork.

Sides

In a planar drawing with the root on the outer face, every fundamental cycle runs clockwise or counterclockwise; call the back edge right or left accordingly. Overlapping cycles are nested iff they run the same way, and the one with the lower lowpoint is outside. This forces pairwise constraints between back edges \(b_1, b_2\) with overlapping cycles:

  • different sides iff \(\id{lowpt}(e_2) < \id{lowpt}(b_1)\) and \(\id{lowpt}(e_1) < \id{lowpt}(b_2)\): at the fork each cycle reaches back past the other branch, so neither can be nested inside the other on the same side;
  • same side iff some other edge \(e'\) leaves an inner vertex \(v_i\) (\(1 < i < k\)) of the shared path with \(\id{lowpt}(e') < \min\{\id{lowpt}(b_1), \id{lowpt}(b_2)\}\): the cycle through \(e'\) encloses both or neither.

An LR partition is an assignment of sides satisfying all these constraints (equivalently, the fork conditions of the definition). Theorem (de Fraysseix & Rosenstiehl): \(G\) is planar iff it has an LR partition, for any DFS orientation.

About this tab: a polynomial-time test via the constraint graph

The constraints of the criterion tab are pairwise, so they form a signed constraint graph: one vertex per back edge, an edge labelled same (+1) or different (−1) for each constrained pair (a pair may get both). An LR partition is exactly a 2-colouring that respects all labels, which exists iff the constraint graph is balanced: no cycle has an odd number of different edges.

  1. Pairs. For every pair of back edges with overlapping fundamental cycles, find the shared tree path and the fork and test the two conditions (one step per pair; the right panel shows the inequalities).
  2. 2-colouring. Breadth-first search: the first back edge of each component is left; a neighbour along a same edge gets the same side, along a different edge the other side.
  3. Result. If an edge is violated, the BFS tree paths to its ends plus the edge form a cycle with an odd number of different edges: no LR partition, so \(G\) is not planar. Otherwise the colouring is an LR partition and \(G\) is planar.

There are \(O(m^2)\) pairs and each test walks two tree paths, so this is a polynomial-time test, but not a linear one. The linear-time test never builds the constraint graph: it keeps its 2-colourings implicitly in the stack of conflict pairs.

About this tab: seeing the embedding

What the test outputs

For a planar graph, phase 3 of the left-right test produces a rotation system: for every vertex, a cyclic order of its neighbours (shown on the right). A rotation system describes a planar embedding: a crossing-free drawing exists in which the edges leave every vertex in exactly this clockwise order. This tab draws it.

Your drawing first

The first step shows the input drawing. If it has no crossings, its faces are tinted. Planar graphs often have many embeddings; the one found by the test need not be yours (for instance, a face that is bounded in your drawing may become the outer face).

Drawing the embedding

The DFS tree grows upwards, and the children of every vertex appear from left to right in the order of the rotation. Every back edge is routed around the tree on its side, at a distance given by its nesting level: one more than the largest level of the back edges nested inside it. Why this has no crossings: in the embedding the tree has a single face, so a walk around the tree meets every back edge twice, and these pairs are nested like parentheses. Nested back edges get smaller distances and stay inside, disjoint ones never meet. A back edge leaves its source at the position the rotation prescribes and must enclose everything inside its fundamental cycle, so it often wraps around the subtree above its source before running down on its side. Colours: blue = left, magenta = right, as in the linear-time test.

Build-up, faces, Euler

First the vertices move from your coordinates to their places in the DFS tree, one per step in DFS order (a tree edge takes its final shape once both ends have arrived); the back edges stay straight and faint meanwhile. Then the back edges are routed one by one, innermost first (in order of nesting level), so the nested shells grow from the inside out. With all at once, each of the two stages is a single step. Consecutive steps are animated. Hover an edge to see it and, for a back edge, its fundamental cycle and its orientation (right = clockwise); hover a face in the list. Then the faces are traced in the rotation system: arriving at a vertex along an edge, continue with the next edge in clockwise order. The face around the root's lowest corner is the outer face. Finally Euler's formula \(n - m + f = 2\) is checked for every connected component.

About this tab: the left-right planarity test, phase by phase

The idea: every cycle turns left or right

Run a DFS and orient \(G\) as in the lowpoint tab. Every back edge \(b = x \hookrightarrow u\) closes a fundamental cycle \(C(b)\): the tree path from \(u\) up to \(x\), then \(b\). In a planar drawing with the root on the outer face, every \(C(b)\) runs clockwise or counterclockwise; call \(b\) right or left accordingly. Two fundamental cycles that share edges overlap in a tree path; the last shared tree edge \(u\to v\) and the two edges \(e_1, e_2\) out of \(v\) along which they continue form a fork. Two overlapping cycles are nested iff they turn the same way, and the one with the lower lowpoint is outside.

LR partition. A split of the back edges into left and right such that at every fork \(u\to v\), \(e_1, e_2\): (1) all return edges of \(e_1\) ending strictly higher than \(\id{lowpt}(e_2)\) are on one side, and (2) all return edges of \(e_2\) ending strictly higher than \(\id{lowpt}(e_1)\) are on the other side. Theorem (de Fraysseix & Rosenstiehl): \(G\) is planar iff it has an LR partition, for any DFS orientation. The test decides whether an LR partition exists by building one implicitly; Brandes (2009) gives the pseudocode used here.

Edge-count test

A simple planar graph with \(n > 2\) vertices has at most \(3n-6\) edges (Euler's formula). Denser graphs are rejected at once, and afterwards \(m = O(n)\). Switch density test off to see the actual test reject \(K_5\).

Phase 1: orientation, lowpoints, nesting depth (dfs1)

dfs1 is the lowpoint computation of the first tab with three additions: it records the DFS roots, it also computes the second lowpoint \(\id{lowpt2}(e)\) (the height of the second-lowest return point), and it gives every edge a nesting depth \(\id{nd}(e) = 2\,\id{lowpt}(e) + [\,e \text{ is chordal}\,]\), where \(e\) out of \(v\) is chordal if it has at least two return points, i.e., \(\id{lowpt2}(e) < \id{height}(v)\). Sorting the outgoing edges \(E^+(v)\) by nesting depth (a bucket sort, since \(0 \le \id{nd} \le 2n\)) orders them from the outside in: a lower lowpoint means further outside, and with equal lowpoints an edge with a single return point goes outside a chordal one.

Phase 2: testing (dfs2)

dfs2 walks the same DFS tree again, visiting the children of every vertex in nesting order. It never builds the constraints explicitly. Instead it keeps them as:

  • intervals \(I = [\id{low}, \id{high}]\): lists of return edges that must all be on the same side, linked by \(\id{ref}\) from the edge with the highest return point (\(\id{high}\)) to the lowest (\(\id{low}\));
  • conflict pairs \(P = (L, R)\): two intervals that must be on different sides. Which one is left is not decided yet: a pair may still be swapped as a whole;
  • the stack \(S\) of conflict pairs for all tree edges on the current dfs2 path. \(\id{stackBottom}[e_i]\) remembers the top of \(S\) before \(e_i\) was explored, so the pairs above it are exactly the constraints of \(e_i\)'s return edges.

At vertex \(v\) with parent edge \(e\) and outgoing edges \(e_1, \ldots, e_d\) in nesting order:

  • a back edge \(e_i\) pushes the pair \((\emptyset, [e_i, e_i])\); a tree edge \(e_i\) is explored recursively.
  • If \(e_i\) has a return edge and \(i = 1\), nothing needs to be merged: \(e_1\) has the lowest lowpoint among the edges out of \(v\), and its lowest return edge \(\id{lowptEdge}[e_1]\) is recorded as \(\id{lowptEdge}[e]\).
  • For \(i \ge 2\), addConstraints merges the constraints of \(e_i\) into those of \(e_1, \ldots, e_{i-1}\):
    1. It pops all pairs above \(\id{stackBottom}[e_i]\) (the return edges of \(e_i\)). The ones ending strictly above \(\id{lowpt}(e)\) must all be on the same side, by condition 2 at the fork of \(e_1\) and \(e_i\) (the lowest return edge of \(e_1\) reaches down to \(\id{lowpt}(e)\)); they are merged into one interval \(P.R\). If a popped pair has return edges of \(e_i\) on both sides, this is impossible: not planar. Return edges ending exactly at \(\id{lowpt}(e)\) are not constrained by this fork; they are aligned with \(\id{lowptEdge}[e]\) (same side, via \(\id{ref}\)).
    2. It then pops further pairs as long as one of their intervals conflicts with \(e_i\), i.e., contains return edges of earlier \(e_j\) ending strictly above \(\id{lowpt}(e_i)\). By condition 1 at the fork of \(e_j\) and \(e_i\), these must be on the other side than the return edges of \(e_i\): the conflicting interval is merged into \(P.L\), its partner into \(P.R\). If both intervals of a pair conflict: not planar.
    3. The new pair \(P\) is pushed.
  • When \(v\) is done, trimBackEdges(\(u\)) for the parent \(u\) of \(v\) removes the back edges that end at \(u\): they are return edges of edges out of \(v\), but not of \(e\), so they impose no further constraints. Pairs that end entirely at \(u\) are dropped and their sides become final (the left interval gets \(\id{side} = -1\)); the top pair is trimmed from above. Finally \(e\) gets a \(\id{ref}\) to its highest return edge: a tree edge lies on the side of its highest return edge.

If dfs2 finishes without a halt, the constraints are consistent and \(G\) is planar.

Phase 3: embedding (sign, sort, dfs3)

Sides are stored relatively: \(\id{side}[e] = \pm 1\) says whether \(e\) is on the same or the other side as \(\id{ref}[e]\). sign(\(e\)) follows the \(\id{ref}\) chain, multiplies the signs and stores the absolute side (\(-1\) = left). Multiplying the nesting depths by the signs and sorting again orders the outgoing edges of every vertex around it: the left edges from the innermost to the outermost, then the right edges from the outermost to the innermost. dfs3 then inserts each back edge into the adjacency list of its target, directly after (right) or before (left) the tree edge into the subtree it comes from. The result is a planar embedding (a rotation system); the page traces its faces and checks Euler's formula \(n - m + f = 2\) for every connected component.

Non-planar graphs: a Kuratowski certificate

After a halt (or a failed edge-count test) the page runs kuratowskiSubgraph: it goes through the edges once and deletes every edge whose removal keeps the graph non-planar, using the test as an oracle. Every edge that stays was needed when it was tested, and the graph only shrinks afterwards, so the result is a minimal non-planar subgraph: by Kuratowski's theorem a subdivision of \(K_5\) (five branch vertices of degree 4) or \(K_{3,3}\) (six of degree 3). This takes \(m\) tests, \(O(n^2)\) time; it is not part of the linear-time algorithm.

Format (Sedgewick & Wayne Graph): the number of vertices V, the number of edges E, then E lines v w with 0 ≤ v, w < V. The graph must be simple (no self-loops, no parallel edges). A third number on an edge line (a weight) is ignored.

Drawing: after the edges, optionally add exactly V lines x y (any scale, y pointing down) to fix the drawing of G; graphs exported from the graph editor have these lines. Without them, the vertices are placed on a circle.

Adjacency order: with Bag, neighbours appear in reverse order of the edge lines (as in the book's Bag); with input, in the order of the edge lines. This decides the DFS.
