Constructing the string-matching automaton

Grow the automaton Aj for P[0..j) one state at a time. Stage 1 finds every new transition by running Aj from scratch on P[1..j)·c; stage 2 notices that all these runs pass through the same state x and simply copies its column.

About this page — conventions and what to look for

Input. Only the pattern is needed. Σ defaults to the characters occurring in P; give it explicitly (e.g. abc) if the alphabet is larger than the set of pattern characters.

Stage 1: simulate Aj from scratch. The automaton is built inductively. Aj, the automaton for P[0..j), is drawn inside the frame; it has the states 0, …, j and all transitions out of 0, …, j−1. To get Aj+1, add state j+1 with the match edge δ[j][P[j]] := j+1, and for every other character c set δ[j][c] to the state in which Aj ends after reading P[1..j)·c. Why that is right is shown in the box “why Aj suffices”: state q means “we have seen P[0..q) until here, but no longer prefix of P”. On a mismatch the text ends with P[0..j)·c, which is not a prefix of P, so the new longest matched prefix P[0..q′) starts at the earliest inside P[1..j)·c — hence q′ ≤ j, and Aj can compute it. Every simulation is shown character by character, on purpose: all runs for one column follow the same path through P[1..j) and end in the same state, and only the last character differs. Tick highlight x to mark that state in green (it is off by default: on a first pass it is a distraction, on the second it is the point). The edge that a new table entry adds is drawn growing out of its source state. That costs Θ(m²σ) simulated transitions in total.

Stage 2: the efficient version. The table is filled column by column. Column j holds all transitions out of state j. On a mismatch in state j the automaton has to continue exactly as it would after reading P[1..j) — and the state for that is x, which is already known. So the whole column x is copied into column j (shaded), a single entry is overwritten by the match edge δ[j][P[j]] := j+1, and then x is advanced by feeding it P[j]. The strip on the left shows the invariant: P[1..j), the string that x stands for.

Colours. Green is the failure state x — the state, the column of the table it is copied from, and the edge it follows when it is updated; red is the state whose column is currently being built.

Cost. Every entry is written exactly once: Θ(mσ) time and Θ(mσ) space. The chips count the writes. Tick one step per copied entry to slow the copying down to single table cells.

The automaton shows only the states that exist so far, but keeps room for all of them, so the picture does not move while it grows; edges with a common target share a label.
