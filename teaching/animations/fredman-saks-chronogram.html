The chronogram method  ·  a lower bound, as an experiment

Dynamic prefix parity — maintain x ∈ {0,1}m under Change(i,a) and Prefix(j) — and with it dynamic rank needs Ω(log m / log log m) probes per operation in the cell probe model with w = log m (Fredman & Saks 1989). The proof charges a query one probe for every epoch of the past. On this page every object of the proof — stamps, the “forgetful” memories DS(i), their answer vectors — is computed from a real data structure on a small instance. The argument on the right follows the presentation in Miltersen's survey (§4.2), with its slips corrected; switch Proof to follow the original Fredman–Saks argument (amortized, a query after every update) on the same kind of instances instead. What is going on
The argument
Setting
D1 Dynamic prefix parity. Maintain x ∈ {0,1}m under Change(i,a): xi ← a, and Prefix(j) = (x1+⋯+xj) mod 2. Cells of w bits, all 0 initially. An operation is a decision assignment tree: it pays one per probe (read one cell, optionally overwrite it); all computation is free. Rank. With S = {i : xi = 1}, Prefix(j) = Rank(j) mod 2 (Rank counting elements ≤ j), and Change(i,a) is an Insert, a Delete or nothing (Rank(i) − Rank(i−1) tells which). So every bound on this page is a bound for dynamic rank.
D2 Hard input. Change(ik,ak), …, Change(i1,a1), Prefix(y) with k = √m; a ∈ {0,1}k and y ∈ {1,…,m} uniform. The positions iu are fixed in advance; only the bits and the query position are random. Update u is the u-th most recent one — indices run backwards in time.
D3 Spread. i1 = m/2, i2 = m/4, i3 = 3m/4, i4 = m/8, …: for every ℓ, the last ℓ updates are pairwise ≥ m/(2ℓ) apart and ≥ m/(2ℓ) from m. Needed only much later, for the Hamming-ball bound (tab 5): it makes the correct answers depend on the recent bits in a robust way. The survey writes this with the letter r (“u,v ≤ r”), which later denotes the number of epochs; any ℓ is meant. Fredman–Saks use the golden-ratio sequence instead, which spreads every window of ℓ consecutive updates by ≥ m/(3ℓ) (select it above).
Chronograms
D4 Epochs. Counting back from the query, epochs 1, …, i together are the last ℓi updates; ℓi = log3i m, and ℓr = √m. So r = log m / (6 log log m) epochs, each log³m times longer than the next more recent one. On this page the ratio is a parameter β (ℓi = βi), because the survey's epochs do not fit into any simulable instance: two epochs already need m ≈ 275.
D5 Stamps. When an update of epoch i changes the content of a cell, the cell's stamp becomes i. A cell's stamp is the epoch of its last change. Pure bookkeeping for the analysis; the data structure knows nothing about stamps. A write that stores the value already present leaves the stamp alone. Stamping every write works as well; the argument needs only (1) DS and DS(i) differ in stamp-i cells only, and (2) a cell stamped < i was written after epoch i.
D6 Forgetting. DS(a) is the memory after all updates; DS(i)(a) is DS(a) with every stamp-i cell restored to its content just before epoch i began. Everything written later, in epochs i−1, …, 1, is kept. DS(i)(a) is a fictitious memory: no sequence of operations need produce it.
D7 Answer vectors. q(a) ∈ {0,1}m: run Prefix(1), …, Prefix(m) on DS(a); q(i)(a): the same code run on DS(i)(a). Each query starts from its own copy of the memory. q(a) are the correct prefix parities; q(i)(a) is not the answer to anything — just what the query code outputs on the tampered memory.
Two counting facts
K1 Few guesses. Fix a1. Then |B| := #{ q(i)(a1∘a2) } ≤ #{ DS(i)(a1∘a2) } ≤ Σj ≤ tℓi−1 C(s, j) 2wj ≤ 20.01ℓi. DS(i) equals the memory at the start of epoch i (fixed by a1), except in the cells written after epoch i: at most t·ℓi−1 of them, among the s ≤ 2m·2wt cells any Change tree can touch. Survey: the sum is printed up to “t·li − 1”; it is t·ℓi−1. And “t < log m” is not enough for the last step: log|B| ≈ (t/log m)²ℓi, so t ≲ 0.09 log m is needed.
K2 Far-apart answers. A := { q(a1∘a2) } has 2ℓi elements, and any ball of radius m/20 contains at most Σj ≤ ℓi/5 C(ℓi, j) ≤ 20.95ℓi of them. Between consecutive recent positions, an element of A equals the centre's segment or its complement; a complement costs ≥ m/(2ℓi) (D3). A ball of radius m/20 lies in a ball of radius m/10 around one of its elements (triangle inequality), which allows ≤ ℓi/5 complemented segments.

C1 WC(Prefix) ≥ maxa, y time of Prefix(y) on DS(a) The worst case is at least the cost of any single input. Survey: “y ∈ {0,1}m” — the query position ranges over {1,…,m}.
C2 ≥ 1⁄2km Σa Σy time of Prefix(y) on DS(a) A maximum is at least the average. From here on the argument is about the average query: it is an average-case bound for the input distribution D2, which implies the worst-case one.
C3 ≥ 1⁄2km Σa Σy Σi=1r [Prefix(y) reads a stamp-i cell of DS(a)] Each probe reads one cell, and each cell carries one stamp, so the number of probes is at least the number of distinct epochs whose stamps the query reads. Cells never changed, or last changed before epoch r, are not counted. A query tree may write. A probe of a cell the query has already overwritten itself reads the query's own value, not a stamped one. (Fredman–Saks assume w.l.o.g. that a query does all its reads before its writes.)
C4 = 1⁄2km Σi Σa #{ y : Prefix(y) reads a stamp-i cell of DS(a) } Exchange the order of summation. In the picture: sum the 0/1 matrix R (epochs × queries) row by row — one epoch at a time — instead of column by column, one query at a time.
C5 ≥ 1⁄2km Σi Σa #{ y : q(a)y ≠ q(i)(a)y } If Prefix(y) reads no stamp-i cell, then DS(a) and DS(i)(a) agree on every cell it reads (they differ in stamp-i cells only), so the tree follows the same path and returns the same answer. Contrapositive: every mismatch lies in row i of R. Only this direction is used. After its first stamp-i read the query may go anywhere on DS(i).
C6 = 1⁄2km Σi Σa dist(q(a), q(i)(a)) Hamming distance on {0,1}m. The rest of the proof shows that each epoch contributes at least 1/40 here, whatever the data structure — provided its updates are cheap.
C7 = 1⁄2km Σi Σa1 Σa2 dist(q(a1∘a2), q(i)(a1∘a2)) Split a at epoch i: a1 ∈ {0,1}k−ℓi are the updates before epoch i, a2 ∈ {0,1}ℓi those of epochs i, …, 1. (Tabs 4, 5.)
C8 ≥ 1⁄2km Σi Σa1 m⁄20 · #{ a2 : dist ≥ m/20 } Keep only the a2 for which the two answer vectors are far apart (tab 5, histogram).
C9 = 1⁄20·2k Σi Σa1 ( 2ℓi − #{ a2 : dist < m/20 } ) Complement count. The survey writes ≥; it is an equality.
C10 ≥ 1⁄20·2k Σi Σa1 ( 2ℓi − |B| · maxc |A ∩ Ball(c, m/20)| ) Pigeonhole: if dist(q, q(i)) < m/20, then q lies in the ball of radius m/20 around the guess q(i) ∈ B; and a2 ↦ q(a1∘a2) is injective.
C11 ≥ 1⁄20·2k Σi Σa1 ( 2ℓi − 20.01ℓi · 20.95ℓi ) K1 and K2.
C12 ≥ 1⁄20·2k Σi 2k−ℓi · 2ℓi/2 = r/40 = log m / (240 log log m) 20.96ℓi ≤ 2ℓi/2 as ℓi ≥ 25; so each epoch contributes 1/40. (Tab 6, next stage.)

Setting
1 PS(n, 2). An array A[1..n] mod 2 under A[i] ← A[i] + δ and sum(j) = Σi≤j A[i] mod 2. The survey's problem, with toggles for assignments. Here every position is updated at most once, from 0, so a toggle by x and an assignment of x coincide.
(1) Sequences u1Q1u2Q2 … umQm, m ≥ 2√n: ud adds xd ∈ {0,1} at ⌊n·(dφ−1 mod 1)⌋; each Qd is a sum query with arbitrary input. Uniform distribution. A query after every update. Here: M = ops updates. The queries of these four structures never write, so they do not change the memory and are not simulated between the updates. As printed in the scan, the position reads “⌊iφ−1⌋ mod n”; Lemma 2 needs the version above.
(2) W = max #writes, w = W/m; R = max #query probes, r = R/m, over all sequences (1). Goal: r = Ω(log n / log(bw log n)). Only totals are bounded: the bound is amortized, and it is a tradeoff between writes and reads. Here w̄ = writes of this sequence / M.
L2 Lemma 2. xd = dφ−1 mod 1 satisfy |xd − xe| ≥ 1/(3|d−e|): the positions updated during the i most recent epochs are ≥ n/(3Li) apart. By the three-distance theorem. Every window of L consecutive updates is spread — the recent window slides with the query.
Chronograms
ch Chronograms. A register changed during the d-th update is relabeled d. A label is a time. Which epoch it belongs to depends on the query one looks at; the colours on this page are the epochs of the selected query Qj.
(3) Epochs of Qj, j ≥ √n: backwards from Qj, the i most recent epochs contain Li = (αw)i updates; q = ⌊log √n / log(αw)⌋ epochs. The ratio αw grows with the update cost — the source of the tradeoff. Toy: Li = βi ≤ √n.
(4) Lemma 1. With w(σ,j,i) = #writes during the i−1 most recent epochs before Qj: w(σ,j,i) ≤ 4wLi−1 ≤ 4Li/α for at least half of the j ≥ √n. Lemma 1: at least half of the m−t+1 windows of t consecutive terms carry ≤ 2At/(m−t+1) (Markov); with t = Li−1 ≤ √n ≤ m/2 this is ≤ 4wt. The only place where amortization enters.
(5) S = the σ with w(σ,j,i) ≤ 4Li/α. Write σ̂ = τμ, μ = the i most recent epochs before Qj; S(i,τ) = the μ with τμ ∈ S. Fix τ, vary μ: the survey's a1 and a2. Only μ with few later writes are used.
Few guesses
(6) q-accessible registers: those some sum(x) meets within its first q probes, from some memory state. γ ≤ n·2qb. The first q probes of each query form a 2b-ary tree of depth q. This replaces the survey's count of all cells a Change can touch — no condition on the update time is needed here.
(7) μ1 ~ μ2 iff the recent q-accessible registers and their contents agree. #classes εi,τ ≤ Σj ≤ 4Li/α C(γ,j) 2bj ≤ 28Li(log n + qb)/α. “Recent” = chronogram after epoch i.
J J(τ,μ,x): run sum(x) with every epoch-i register reporting its value at the end of τ; J = ∞ after more than q probes. If J ≠ sum(x): more than q probes, or an epoch-i register was probed. The same as running on DS(i). μ1 ~ μ2 ⇒ both modified runs see the same contents for q probes ⇒ J(τ,μ1) = J(τ,μ2) =: Vj, one vector per class. Truncation at q probes is harmless: such a query already pays one probe per epoch.
(8) With δ(τ,μ) = dist(Vj, F(τ,μ)):  Ej·n ≥ 1⁄zj Σi≤q Στ Σμ∈S(i,τ) δ(τ,μ). (**): the probes of sum(x) are at least the number of epochs i with μ ∈ S(i,τ) and J(τ,μ,x) ≠ sum(x). F = the correct answers, zj = the number of prefixes before Qj.
Far-apart answers
L3 Lemma 3. The F(τ,μ) form an affine space spanned by Li orthogonal 0/1 vectors, each but possibly one of weight ≥ n/(3Li). At most 2·2.95Li lie within n/30 of any V. The basis vectors are the segments between consecutive recent positions (Lemma 2); the possibly short one is the last segment, which ends at n. The paper leaves the proof to the reader.

Sources, notation, and what the original proof does differently

What the original does differently

  • Amortization. The sequence is u1Q1u2Q2…, a query after every update, and epochs are laid out backwards from every query Qj. Only the total number of writes W is bounded; Lemma 1 (at least half of all windows of t consecutive terms carry at most twice their fair share) turns that into “few writes after epoch i” for at least half of the queries.
  • Positions. Because the recent window slides with j, every window of updates must be spread, not just the suffixes of one sequence: hence the golden-ratio positions and the three-distance theorem (Lemma 2). As printed in the scan, the position reads “⌊iφ−1⌋ mod n”; Lemma 2 and its use make clear that ⌊n·(iφ−1 mod 1)⌋ is meant.
  • Epoch ratio. αw instead of log³m: the epochs adapt to the update cost, which gives the tradeoff r = Ω(log n / log(bw log n)).
  • Which cells matter. Only q-accessible registers — those some query can reach within its first q probes — of which there are ≤ n·2qb, and a query running longer than q probes is cut off (J = ∞): it already pays one probe per epoch. The survey instead counts all cells any Change tree can touch, s ≤ 2m·2wt, which is where its requirement on t comes from.
  • Constants. Distance threshold n/30 around the class vector directly, allowing one short basis vector (the factor 2 in Lemma 3); per-epoch contribution 1/60.

The Fredman–Saks mode on this page

  • The sequence is u1…uM with M = ops; one query Qj is looked at in detail (j), and tabs 1–5 show the argument for that query. Its epochs hold at most √n updates together, so older updates belong to τ (“earlier”).
  • The queries between the updates are not simulated: none of the structures here writes during a query, so they cannot change the memory.
  • w̄ is the number of writes of this sequence divided by M (the paper's w is a maximum over all sequences), and the epoch ratio is the parameter β instead of αw = 400·b·log n·w, which no toy can accommodate.
  • q-accessible registers are computed exactly: the update log gives its own list (its queries are adaptive); the other structures are non-adaptive, so running every query once finds all registers within its first q probes.
  • Truncation matters on small instances: with few epochs, q is small, and a structure whose queries take more than q probes has J = ∞ everywhere (preset “FS: binary tree”). The argument is then trivially satisfied — and uninformative.

Slips in the survey's §4.2, corrected on this page

  • In the first display, y ranges over {1,…,m}, not {0,1}m.
  • The spread property uses r for an arbitrary length; r is also the number of epochs. Likewise k denotes both √m and a “consecutive member”.
  • The count of forgetful memories sums up to t · ℓi−1 (cells written after epoch i), printed as “t·li − 1”; a # is missing there as well.
  • “If the complexity t of Change is less than log m” does not give |B| ≤ 20.01ℓi: the bound is log|B| ≈ t²wℓi−1 = (t/log m)² ℓi, so roughly t ≤ 0.09 log m is needed. The theorem survives: either Change costs ≥ 0.09 log m, or Prefix costs ≥ log m / (240 log log m).
  • Rank is defined with “< x” in §2 and “≤ x” in §4.2; the reduction needs ≤.
